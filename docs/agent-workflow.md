# 写作助手：任务、候选与改动审阅

右栏和正文快捷条共用 Agent 流程。设定、角色、伏笔弹窗的“AI 助手”入口也进入同一流程，带上对象引用及当前表单材料。生成不会直接覆盖业务数据。

## 上下文与引用

- 上下文抽屉显示作品资料及分节标题的估算，不含系统提示、聊天历史、当前提问或任务额外材料；Agent 按需调用工具，预览不是实际请求的逐字清单。
- 上下文预算默认 12000 token。普通装配超限时从低优先级分节开始，先逐条省略可精简的资料，不足时丢弃该分节，仍超限再截断剩余内容；Agent 的规划、写作和资料整理分别检查材料，超限可能提示提高预算或缩小范围。设为 0 只关闭应用侧预算限制，已知模型窗口的完整请求检查仍生效，窗口未知时无法硬性检查。
- 单次输出上限为 0 时通常使用服务商默认值，Anthropic 兜底 4096，并非无限；实际长度还受模型与任务限制。
- 角色和设定的 `aiVisible=false` 不可通过引用绕过。未到揭示章节或当前章节未知时默认隐藏；本轮明确 `@` 引用可例外读取未揭示的卡，但不应提前写入正文。开启故事档案时默认只取当前章之前的档案，明确引用可例外读取指定档案；关闭档案开关时不能读取。
- 关闭「选区」后，选中文字不会随本轮发送。输入 `@` 打开候选时，回车先选择引用，不会直接发送；失败后重试沿用该次请求保存的引用、选区和上下文配置。
- 手动校订过的档案重新提取时保留人工内容、补充新事实；模型发现冲突会提示，但仍需人工核对。档案正确时同步改正文，正文正确时手动修正档案；只改正文不会自动覆盖人工档案。

## 交互与写入

- 助手按需读取目录、正文、三级大纲、资料和故事档案；工具读取缺失章纲不会创建空行。
- 资料候选按字段展示原值、新值及变化高亮；确认时可选择字段。
- 正文候选可以在中央写作区审阅，逐处保留或还原，支持上一处、下一处及批量选择。预览不会进入自动保存。
- 应用时服务端从保存的候选重建正文，不接受任意客户端替换文本。
- 批量应用使用 SQLite 事务；任一对象版本冲突时整批回滚。应用状态持久化，重复提交不会重复创建对象。
- 撤回校验应用后的实体快照。有后续人工修改或新增关联时拒绝覆盖撤回。
- 应用前先锁定编辑输入并等待保存完成；服务端成功后同步编辑器草稿与正文，不让旧草稿再次覆盖新稿。
- 设定表单保存带原始版本。异步详情返回也不会覆盖已经开始编辑的本地草稿。

## 实现入口

- `lib/ai/agent/run.ts`：有限轮次的规划与工具执行；正文由独立的流式写手调用生成。
- `lib/ai/agent/schema.ts`：可修改字段白名单、字段类型与正文转义。
- `lib/ai/agent/store.ts`：只读查询、暂存候选、批量应用、冲突校验及撤回。
- `agent_runs`：任务、步骤、引用、候选及应用记录。聊天消息保存运行 ID，历史会话通过 ID 重新读取记录。
- `components/ai/AgentRunCard.tsx`：正文候选、资料字段对比和应用操作。
- `components/editor/AgentReview.tsx`：中央正文的逐处审阅。

规划协议按服务商能力选择原生工具调用或经过 schema 校验的文本 JSON；DeepSeek 使用原生工具，已知 OpenAI 官方端点的文本规划启用 JSON Output。解析失败修复重试一次；仍失败时保留已完成候选并明确报错，不静默换成另一类任务。上限为 12 轮规划、36 次工具调用、3 次正文生成。

上下文读取遵守资料隐藏开关和默认上下文类别开关；明确引用的角色、设定或伏笔可例外读取默认类别开关排除的对象，但不能绕过对象本身的 AI 隐藏设置。对话历史是有标记的裁剪，并非语义总结。

## 验证与范围

事务测试使用临时数据库，工具循环使用模拟 Provider。浏览器验证使用独立书稿数据库和本地 OpenAI 兼容模拟服务；没有调用用户的真实模型，也没有改正式书稿。

已实际验证正文部分应用、未选原文保留、增补段落顺序、设定字段选择及撤回。浏览器验证还发现并修复了旧块级 diff 的新增段落锚点错误，以及 Tiptap `setEditable` 默认派发更新造成的无内容保存。

本版不提供进程崩溃后的自动续跑、任意版本切换或按场重生成。运行记录和已完成候选会保存；真实模型的长篇写作质量与延迟仍需要实际书稿验收。资料关系字段、档案回填及编号重排也没有作为任意写入工具开放。

## 正文后的资料整理

正文候选完成后额外执行一次资料整理，最多提出12张人物、设定或伏笔卡，仍需作者确认才入库。明确要求只写正文、不建卡或选区修改时跳过。每项附可展开的原文引用，并标记来自待确认正文还是已有正文；服务端检查引用逐字存在，不能据此保证模型所有归纳都准确，仍需审阅。

按姓名及别名匹配已有资料。自动整理只填空白字段、合并列表，不覆盖作者已有事实；歧义重名跳过，明确修改请求仍由普通propose工具处理。物品、地点、道路等只在关系到关键剧情时建卡，宁缺毋滥；新卡可附带重要程度（高/中/低），已有卡的重要程度不会被自动覆盖。遵守上下文类别开关与AI隐藏设置。解析失败重试一次，仍失败保留正文并显示整理未完成。整理调用的token计入本轮usage。

聊天用资料回执和分类标签收纳改动，展开后可看卡片、原文依据及逐字段差异；应用后可打开资料继续编辑。左侧资料库复用同一套人物/地点/伏笔预览，展示身份、性格、目标和标签。

## 资料弹窗与用量

资料列表保留卡片样式。角色、设定和伏笔的编辑弹窗改用同一档案布局：顶部名称直接编辑，正文、关联和可见性按页签组织，保存与取消固定在底部。页签切换只改变视图，不清空草稿。

聊天消息末尾的数据库图标打开本次用量；输入框底部一行显示今日token、预估费用和上下文比例。日汇总仍按配置单价预估，不是账户账单。单次Agent优先显示可识别的接口费用，保留USD或CNY；部分调用未返回费用时只标为部分费用，不当作完整账单。兼容接口金额必须明确币种；OpenRouter的usage.cost按其公开协议识别为USD。没有费用和单价时显示费用未知，不显示免费。没有usage时标记本地token估算。

Tooltip使用独立命名的悬浮分组，避免外层group激活所有提示。包装IconButton时移除重复的原生title，面板顶部提示向下展开。

资料编辑弹窗不再显示逐字段AI按钮或“补全/交给助手”两组操作。统一的“AI 助手”入口只引用当前卡片、附带草稿并聚焦写作台输入框，不自动发送，不覆盖已输入的问题。已保存资料使用真实@引用，未保存资料标记为草稿；新输入按会话保留快照，移除引用后不再携带该卡片快照。通用Button默认居中，浮窗底部为缩放柄预留间距。

界面品牌强调色统一为墨蓝，正文和字段差异继续用绿/红表达新增与删除。资料来源会区分已有正文、待确认候选、已应用正文、撤回/丢弃的候选；部分采用正文后，也会标记引用未被采用的情况，避免把未落库内容当成已写事实。


## 进展与滚动

新任务的关键进展按发生顺序保留，当前工具步骤只更新自身状态，详细工具调用默认折叠。正文写作阶段显示实时字数和草稿，完成的正文与资料候选保留审阅入口；停止或出错时保留尚未完成的草稿供查看。

停留在对话底部会自动跟随输出；向上翻阅后，新消息不会把阅读位置拉回底部，点击「有新进展 · 回到底部」可恢复跟随。进展随任务保存，刷新或重新打开会话可恢复。旧任务没有记录这些说明，仍可查看已有执行步骤与最终回执，无法补回历史过程文本。

沉浸写作时，右上角仍有「打开 AI 助手」入口，也可按 Alt+J。宽屏按需展开右栏，窄屏使用抽屉；呼出或关闭助手不会退出沉浸模式。

助手在同一个实例中保活，折叠、沉浸和宽窄屏切换只调整布局，不重新创建对话。准备阶段禁用发送，生成阶段提供停止；发送入口的同步锁防止双击并发，回车也遵守同一运行状态。DeepSeek DSML 工具封套会先转成统一调用结构，再走原有工具白名单、参数校验、权限和待确认改动流程；普通说明和损坏封套仍走协议修复，不猜测执行操作。


## 上下文缓存与费用

写作请求按「固定规则与文风 → 稳定资料 → 当前正文 → 本次任务」组织。资料按实体标识排序，对象键规范排序；不把创建、更新时间戳当成写作事实重复发送。当前正文仅放一份，上一轮候选在规划消息里只保留标识、状态与修改字段，按需读取具体内容。事实变化会改变对应前缀，不会为了缓存继续使用旧设定。

OpenAI 兼容接口的 DeepSeek `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 与 `prompt_tokens_details.cached_tokens` 会进入本轮用量。缓存 token 已包含在输入总量里，不额外再加一次。多次模型调用累计时，未报告缓存的输入保持未知；不把它们算成已知未命中。消息、运行记录、日志与每日统计均保留这些信息。

设置 → AI 上下文 → 用量与费用支持普通输入、缓存命中输入、输出三档人民币单价。缓存单价留空代表未知，显式填 0 才表示免费；获取并采用 DeepSeek 官方单价时同时填写三档。历史未记录的缓存无法补算，仍标为未报告。小额费用保留更多小数。

服务商完整返回费用时优先显示接口金额及原币种；否则按已配置单价估算。每日和累计金额按当前全局单价计算，混用模型或价格变化时不等于账户实付账单。尚未支持的缓存字段不会冒充命中或免费。

缓存命中由服务商决定，不能保证百分比，也不会为了命中把全书设定塞入上下文。实测方法及限制见 [缓存验证](cache-validation.md)。

长篇工作区默认只返回最近 12 章、当前章前后 2 章及明确引用的章节，并保留全书章号和总章数；角色、设定、伏笔目录各取前 40 项并给出总数。完整资料可通过 list 的 query、offset、limit 搜索和分页获取，列表摘要最多 200 字，全文仍需 read。

应用正文后自动回到可编辑章节；卡片的「打开正文 · 继续编辑」直达当前正文。「查看历史改动」在独立抽屉中显示本轮快照，不替换编辑器。待确认审阅在应用或丢弃后自动关闭。新建章节导航先刷新目录，避免旧目录将新章节误判为不存在。AI 快捷任务收进格式工具栏的「AI 助手」下拉菜单。新增章节的绿色预览合并为一处，点击「保留」即可应用；已有正文显示红色删除与绿色新增，可逐处保留/还原，全部审阅后自动写入，也可一次全部保留。全部还原只丢弃候选，不创建空章节。

审阅界面采用蓝色状态与操作卡片，原文、修订稿分别标注，新增与删除仅在文字层保留绿标/红色划线。批量操作和逐处操作都使用同一提案写入流程。

## 工具调用可靠性

DeepSeek 的 OpenAI 兼容通道优先使用声明的原生工具函数（workspace/list/read/propose/write_chapter/reject_change/read_archive/respond），规划阶段默认关闭 thinking 并要求工具调用；用户显式开启已适配模型的思考档位后，使用 auto 工具选择并在本轮内保留必要的推理历史。普通讨论和完成说明通过 respond 返回；写手仍输出正文，不强制套工具格式。每个工具参数继续经过原有 schema、可见性、目标归属与候选确认流程，原生返回不直接写库。

已知 OpenAI 官方端点的文本规划启用 JSON Output；未知兼容端点和其他协议保留原有文本规划。有效的文本 DSML 封套仍可兼容，但不猜测修补损坏的调用。每轮最多12个调用、总计最多36个调用，均通过同一执行器。损坏输出仅保存在脱敏诊断里，不回灌成下一轮的 assistant 示例；成功结果归一为标准 JSON 对话记录，空白返回也进入一次修复流程。原生工具定义计入上下文预算和缺失 usage 时的输入估算。

实测覆盖、失败方案与当前限制见 [真实模型连续任务回归记录](agent-protocol-validation.md)。

输出质量与多轮实测记录见 [agent-quality-validation.md](./agent-quality-validation.md)。
