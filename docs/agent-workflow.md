# 写作助手：任务、候选与改动审阅

右栏和正文快捷条共用 Agent 流程。设定、角色、伏笔弹窗的“AI 助手”入口也进入同一流程，带上对象引用及当前表单材料。生成不会直接覆盖业务数据。

## 交互与写入

- 助手按需读取目录、正文、三级大纲、资料和故事档案；工具读取缺失章纲不会创建空行。
- 资料候选按字段展示原值、新值及变化高亮；确认时可选择字段。
- 正文候选可以在中央写作区审阅，逐处保留或还原，支持上一处、下一处及批量选择。预览不会进入自动保存。
- 应用时服务端从保存的候选重建正文，不接受任意客户端替换文本。
- 批量应用使用 SQLite 事务；任一对象版本冲突时整批回滚。应用状态持久化，重复提交不会重复创建对象。
- 撤回校验应用后的实体快照。有后续人工修改或新增关联时拒绝覆盖撤回。
- 应用前先锁定编辑输入并等待保存完成；服务端成功后同步编辑器草稿与正文，不让旧草稿再次覆盖新稿。
- 设定表单保存带原始版本。异步详情返回也不会覆盖已经开始编辑的本地草稿。

## 实现入口

- `lib/ai/agent/run.ts`：有限轮次的规划与工具执行；正文由独立的流式写手调用生成。
- `lib/ai/agent/schema.ts`：可修改字段白名单、字段类型与正文转义。
- `lib/ai/agent/store.ts`：只读查询、暂存候选、批量应用、冲突校验及撤回。
- `agent_runs`：任务、步骤、引用、候选及应用记录。聊天消息保存运行 ID，历史会话通过 ID 重新读取记录。
- `components/ai/AgentRunCard.tsx`：正文候选、资料字段对比和应用操作。
- `components/editor/AgentReview.tsx`：中央正文的逐处审阅。

现有 Provider 接口不支持统一原生工具调用，因此本版使用经过 schema 校验的 JSON 指令。解析失败修复重试一次；仍失败时保留已完成候选并明确报错，不静默换成另一类任务。上限为 12 轮规划、36 次工具调用、3 次正文生成。

上下文读取遵守资料隐藏开关和默认上下文类别开关；明确引用可以读取被默认类别开关排除的对象，但不能绕过对象本身的 AI 隐藏设置。对话历史是有标记的预算裁剪，并非语义总结。

## 验证与范围

事务测试使用临时数据库，工具循环使用模拟 Provider。浏览器验证使用独立书稿数据库和本地 OpenAI 兼容模拟服务；没有调用用户的真实模型，也没有改正式书稿。

已实际验证正文部分应用、未选原文保留、增补段落顺序、设定字段选择及撤回。浏览器验证还发现并修复了旧块级 diff 的新增段落锚点错误，以及 Tiptap `setEditable` 默认派发更新造成的无内容保存。

本版不提供进程崩溃后的自动续跑、任意版本切换或按场重生成。运行记录和已完成候选会保存；真实模型的长篇写作质量与延迟仍需要实际书稿验收。资料关系字段、档案回填及编号重排也没有作为任意写入工具开放。

## 正文后的资料整理

正文候选完成后额外执行一次资料整理，最多提出12张人物、设定或伏笔卡，仍需作者确认才入库。明确要求只写正文、不建卡或选区修改时跳过。每项附可展开的原文引用，并标记来自待确认正文还是已有正文；服务端检查引用逐字存在，不能据此保证模型所有归纳都准确，仍需审阅。

按姓名及别名匹配已有资料。自动整理只填空白字段、合并列表，不覆盖作者已有事实；歧义重名跳过，明确修改请求仍由普通propose工具处理。遵守上下文类别开关与AI隐藏设置。解析失败重试一次，仍失败保留正文并显示整理未完成。整理调用的token计入本轮usage。

聊天用资料回执和分类标签收纳改动，展开后可看卡片、原文依据及逐字段差异；应用后可打开资料继续编辑。左侧资料库复用同一套人物/地点/伏笔预览，展示身份、性格、目标和标签。

## 资料弹窗与用量

资料列表保留卡片样式。角色、设定和伏笔的编辑弹窗改用同一档案布局：顶部名称直接编辑，正文、关联和可见性按页签组织，保存与取消固定在底部。页签切换只改变视图，不清空草稿。

聊天消息末尾的数据库图标打开本次用量；输入框底部一行显示今日token、预估费用和上下文比例。日汇总仍按配置单价预估，不是账户账单。单次Agent优先显示可识别的接口费用，保留USD或CNY；部分调用未返回费用时只标为部分费用，不当作完整账单。兼容接口金额必须明确币种；OpenRouter的usage.cost按其公开协议识别为USD。没有费用和单价时显示费用未知，不显示免费。没有usage时标记本地token估算。

Tooltip使用独立命名的悬浮分组，避免外层group激活所有提示。包装IconButton时移除重复的原生title，面板顶部提示向下展开。

资料编辑弹窗不再显示逐字段AI按钮或“补全/交给助手”两组操作。统一的“AI 助手”入口只引用当前卡片、附带草稿并聚焦写作台输入框，不自动发送，不覆盖已输入的问题。已保存资料使用真实@引用，未保存资料标记为草稿；新输入按会话保留快照，移除引用后不再携带该卡片快照。通用Button默认居中，浮窗底部为缩放柄预留间距。

界面品牌强调色统一为墨蓝，正文和字段差异继续用绿/红表达新增与删除。资料来源会区分已有正文、待确认候选、已应用正文、撤回/丢弃的候选；部分采用正文后，也会标记引用未被采用的情况，避免把未落库内容当成已写事实。
