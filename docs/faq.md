# 常见问题（FAQ）

## 1. 砚田是什么？和「马良写作」这类产品是什么关系？

砚田是一个**源码公开、本地优先**的中文长篇小说 AI 创作工作台：作品/卷/章三级结构、三级大纲、角色与设定资料卡、故事档案、3 个内置 AI 智能体（主编 / 写作 / 设定，人设可改，也可自定义）与资料助手、逐段 diff 改稿。它在产品思路上参考了公开可见的线上 AI 写作产品（信息架构、上下文装配、档案等概念），但**代码全部独立实现（clean-room）**，不包含任何上游闭源代码，也不需要它们的账号或订阅。详见 README 的「致谢与灵感来源」。

## 2. 需要注册、登录、付费或联网吗？

不需要注册和登录，也没有订阅与额度。程序跑在你自己电脑（或你控制的服务器）上：

- 不接模型也能编辑书稿，并使用离线**演示模式**中的模板功能；多步 Agent 需要配置可用的实际模型，演示模型不会执行这些任务。
- 要用真模型时，自己填 API Key 直连厂商，费用直接付给厂商，砚田不抽成。
- 使用云端模型时需要连接你配置的服务；本机 Ollama 可在模型安装完成后本地运行。

## 3. 我的稿子和 API Key 存在哪里？会不会上传？

全部存在本机：

- 数据库：`data/yanfield.db`（一个 SQLite 文件，可用 `YANFIELD_DB_PATH` 改位置）。
- 密钥：同一数据库的 `providers` 表，**明文存储**（本地应用常见做法）。请不要把这个文件发给别人，也不要把整个项目目录传到公开仓库。
- 砚田本身不提供用户遥测、统计或云同步。使用云模型时，请求中实际包含的书稿和上下文会发送给你配置的模型服务；服务商是否记录内容，取决于其隐私政策。Next.js 自带匿名遥测，可设置 `NEXT_TELEMETRY_DISABLED=1` 关闭；README 的启动命令和 Docker 默认已关闭。

## 4. 怎么备份和迁移？换电脑怎么办？

停掉砚田，复制 `data/` 目录（`yanfield.db`，以及可能存在的 `yanfield.db-wal` / `yanfield.db-shm`）到新机器同一路径，再启动即可。也可以用「设置 → 数据 → 导出」把书稿导成 Markdown/TXT 长期归档。SQLite 文件可以随时用 `sqlite3` 等工具打开检查，不怕「被平台锁住」。

## 5. 能接哪些大模型？没有 API Key 能玩吗？

支持五类：OpenAI 兼容（DeepSeek、OpenAI、Moonshot、智谱、硅基流动、OpenRouter、one-api 网关、vLLM…）、Anthropic Claude、Google Gemini、本地 Ollama、内置演示模式。设置页选品牌后填写 Key，主动拉取或手动添加模型，再选择默认模型并测试连接；环境变量也可在初始化时创建 Provider。没有 Key 可以使用离线模板；若想使用 Agent，可配置本机 Ollama 等实际模型，安装程序和下载模型可能需要联网。逐类配置见 [ai-providers.md](./ai-providers.md)。

## 6. 为什么不是直接 `npm i` 就能跑？Node 版本为什么要 22.13+？

砚田用 Node 内置的 `node:sqlite` 数据库驱动，**零原生依赖**（不用编译 better-sqlite3，Docker 镜像也小）。`node:sqlite` 从 Node 22.5 引入，从 **22.13 / 23.4** 起不再需要 `--experimental-sqlite` 标志，所以推荐 Node ≥ 22.13（或直接用 24 LTS）。用更老的 Node 会启动失败。

## 7. 为什么 AI 不直接把改写结果写进正文？

因为长篇小说最怕「AI 悄悄改坏了你还不知道」。正文类 AI 产出以**建议**形式出现；可以逐处「保留」或「还原」，也可以批量操作，确认后才写回正文，未保留的部分保持原样。这样既有 AI 的效率，又保留作者最终决定权。

## 8. 「上下文装配」和「故事档案」是干什么的？为什么 AI 会忘记前面的设定？

模型一次能读的内容有限，长篇不适合每次都塞入全文。砚田的做法是：

- **上下文预览**：按勾选的维度估算作品资料和分节标题的 token，显示普通装配中被裁掉或截断的部分；不包括系统提示、聊天历史、当前提问和任务额外材料。Agent 会按需读取，预览不是它每次请求的完整清单。
- **预算**：默认上下文预算为 12000 token；Agent 规划、写作和资料整理分别检查材料，超限时可能要求缩小任务范围。设为 0 只关闭应用侧预算限制；已知模型窗口的完整请求仍会检查，窗口未知时无法硬性检查。输出上限为 0 通常由服务商决定，Anthropic 兜底 4096，并非无限。
- **故事档案**：把章节沉淀成结构化档案（摘要、角色状态、资源总账、时间线、伏笔），开启档案时默认取当前章之前最近 N 章的档案；明确引用可例外读取指定档案，关闭档案开关时不能读取。写作台左栏「档案」页签的「一键补建全书档案」只补「有正文、还没档案」的章；都建好了会马上结束，不会再请求模型。

出现「忘了设定」时，先检查上下文开关、相关资料是否被读取，以及角色/设定的 `aiVisible` 是否开启。设置了 `revealAtChapter` 的卡在揭示前默认隐藏，没有当前章节时也隐藏；本轮明确 `@` 引用可例外读取未揭示的卡，但不能绕过 `aiVisible`。

档案过期时请核对正文并重新提取。人工校订过的档案会保留作者内容并补充新事实；模型发现冲突时会提示，但可能有遗漏。若人工档案正确，请同步修改正文；若正文正确，请手动修正档案。只修改正文不会自动覆盖人工档案。

## 9. 能导入我已有的稿子吗？能导出 Word 吗？

- 导入：设置 → 数据 → 导入 TXT，支持用正则识别「第一章 / 第1章 / Chapter 1」等标题自动拆章，先预览再导入。
- 导出：按章 / 按卷 / 全书导出 Markdown 或 TXT。**0.1.0 暂不支持直接导出 .docx**，可以先导出 Markdown 再用 Pandoc/Word 打开；需要 Word 排版可以按 [roadmap.md](./roadmap.md) 的节奏关注后续版本。

## 10. 手机能用吗？能多人协作吗？遇到报错怎么查？

- 手机：布局是响应式，窄屏可用，但三栏编辑器体验以桌面浏览器为准；没有 App。
- 协作：0.1.0（开发中，未发布）是单机单人（无账号体系）。分享方式为导出文件，或把实例部署到你自己的服务器上单独使用。多人实时协作不在近期计划内。
- 报错：先点设置里的「测试连接」；再看面板上的错误原文（401/404/429 最常见），最后查「AI 调用日志」。上下文超长、Ollama 未启动、baseUrl 多写 `/v1` 是新手三大坑。

## 11. 重置示例会删除我的作品吗？

「设置 → 数据 → 重新生成示例作品」只新增示例。命令 `pnpm db:seed` 则会删除作者为「砚田示例」**或标题为《潮信》《长夜行》**的作品，即使是你自己创建的同名作品也会删除；它还会删除内置提示词预设，相关修改可能丢失。执行前请停服、备份数据库。重启后只有数据库里没有任何作品时才自动创建示例。
