# 常见问题（FAQ）

## 1. 砚田是什么？和「马良写作」这类产品是什么关系？

砚田是一个**源码公开、本地优先**的中文长篇小说 AI 创作工作台：作品/卷/章三级结构、三级大纲、角色与设定资料卡、故事档案、8 位 AI 智能体、逐段 diff 改稿。它在产品思路上参考了公开可见的线上 AI 写作产品（信息架构、上下文装配、档案等概念），但**代码全部独立实现（clean-room）**，不包含任何上游闭源代码，也不需要它们的账号或订阅。详见 README 的「致谢与灵感来源」。

## 2. 需要注册、登录、付费或联网吗？

不需要注册和登录，也没有订阅与额度。程序跑在你自己电脑（或你控制的服务器）上：

- 不接模型也能用：首次启动自带离线**演示模式**，所有 AI 流程都能走通（结果是模板生成的）。
- 要用真模型时，自己填 API Key 直连厂商，费用直接付给厂商，砚田不抽成。
- 唯一需要公网的是你配置的模型服务本身。

## 3. 我的稿子和 API Key 存在哪里？会不会上传？

全部存在本机：

- 数据库：`data/yanfield.db`（一个 SQLite 文件，可用 `YANFIELD_DB_PATH` 改位置）。
- 密钥：同一数据库的 `providers` 表，**明文存储**（本地应用常见做法）。请不要把这个文件发给别人，也不要把整个项目目录传到公开仓库。
- 砚田没有任何遥测、统计或云同步；请求只会发往你配置的模型服务。模型服务是否记录你的内容，取决于厂商的隐私政策。

## 4. 怎么备份和迁移？换电脑怎么办？

停掉砚田，复制 `data/` 目录（`yanfield.db`，以及可能存在的 `yanfield.db-wal` / `yanfield.db-shm`）到新机器同一路径，再启动即可。也可以用「设置 → 数据 → 导出」把书稿导成 Markdown/TXT 长期归档。SQLite 文件可以随时用 `sqlite3` 等工具打开检查，不怕「被平台锁住」。

## 5. 能接哪些大模型？没有 API Key 能玩吗？

支持五类：OpenAI 兼容（DeepSeek、OpenAI、Moonshot、智谱、硅基流动、OpenRouter、one-api 网关、vLLM…）、Anthropic Claude、Google Gemini、本地 Ollama、内置演示模式。设置页内置 11 家服务商预设，「选品牌 → 粘 Key → 测试连接」就能接上；Docker / 自托管也可以用 `*_API_KEY` 环境变量在首次启动时自动创建 Provider。没有 Key 也能完整体验：用自带的「离线演示模式」，或在本机跑 Ollama（完全免费、不需联网）。逐类配置样例见 [ai-providers.md](./ai-providers.md)。

## 6. 为什么不是直接 `npm i` 就能跑？Node 版本为什么要 22.13+？

砚田用 Node 内置的 `node:sqlite` 数据库驱动，**零原生依赖**（不用编译 better-sqlite3，Docker 镜像也小）。`node:sqlite` 从 Node 22.5 引入，从 **22.13 / 23.4** 起不再需要 `--experimental-sqlite` 标志，所以推荐 Node ≥ 22.13（或直接用 24 LTS）。用更老的 Node 会启动失败。

## 7. 为什么 AI 不直接把改写结果写进正文？

因为长篇小说最怕「AI 悄悄改坏了你还不知道」。砚田里所有正文类 AI 产出（续写、润色、改写、去 AI 味…）都以**建议**形式出现，用段落级 diff 展示，你逐块勾选「采用」后才写回正文；未采纳的部分保持原样。这样既有 AI 的效率，又保留作者最终决定权。

## 8. 「上下文装配」和「故事档案」是干什么的？为什么 AI 会忘记前面的设定？

模型一次能读的字数有限，长篇写到几十万字必然塞不下全文。砚田的做法是：

- **上下文装配**：每次请求前，按你勾选的维度（总纲→卷纲→章纲→前 N 章摘要→最近档案→角色卡→设定卡→伏笔→文风）组装上下文，并显示每个维度占多少 token、超预算时裁掉了什么。**上下文预算**默认 12000 token（面板里可调，填 0 = 不限），它控制在「输入侧」喂多少资料；另有一个「单次输出上限」控制这次生成写多少。预算别超过所选模型的上下文窗口（模型列表里会显示）。
- **故事档案**：把每章沉淀成结构化档案（摘要、角色状态、资源总账、时间线、伏笔），后续章节用「最近 N 章档案」接续前文。档案页的「一键补建全书档案」只补「有正文、还没档案」的章；都建好了会马上结束，不会再请求模型。

出现「忘了设定」时，先在上下文面板确认对应角色/设定是否被勾选、`aiVisible` 是否为开、`revealAtChapter` 是否已解锁；再检查档案是否已过期（正文改了但档案没重新提取）。

## 9. 能导入我已有的稿子吗？能导出 Word 吗？

- 导入：设置 → 数据 → 导入 TXT，支持用正则识别「第一章 / 第1章 / Chapter 1」等标题自动拆章，先预览再导入。
- 导出：按章 / 按卷 / 全书导出 Markdown 或 TXT。**0.1.0 暂不支持直接导出 .docx**，可以先导出 Markdown 再用 Pandoc/Word 打开；需要 Word 排版可以按 [roadmap.md](./roadmap.md) 的节奏关注后续版本。

## 10. 手机能用吗？能多人协作吗？遇到报错怎么查？

- 手机：布局是响应式，窄屏可用，但三栏编辑器体验以桌面浏览器为准；没有 App。
- 协作：0.1.0（开发中，未发布）是单机单人（无账号体系）。分享方式为导出文件，或把实例部署到你自己的服务器上单独使用。多人实时协作不在近期计划内。
- 报错：先点设置里的「测试连接」；再看面板上的错误原文（401/404/429 最常见），最后查「AI 调用日志」。上下文超长、Ollama 未启动、baseUrl 多写 `/v1` 是新手三大坑。
