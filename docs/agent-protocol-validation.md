# Agent 协议真实模型回归

2026-11-03，使用真实 DeepSeek API / `deepseek-flash`，通过本机独立测试库中的生产 Agent SSE 路由连续执行任务。书稿、人物和设定均为合成内容；没有向模型发送真实作品，没有应用到用户书稿。密钥仅在测试代理内存中使用，未写入源码、数据库或测试报告，测试结束后关闭代理并清除引用。

## 观察到的问题

只读检查实际失败记录，发现损坏的 DSML 参数/闭合标签，以及合法 JSON 中一次8项读取被旧5项上限拒绝。旧的修复请求还会把坏格式原样回灌给模型，容易反复模仿。

仅开启 JSON Output 的初轮真实测试为6/8通过，继续追问仍两次返回带DSML残片的无效内容。将整轮计划包装为单个函数的尝试也不稳定（1/8通过），未采用。这些失败不能靠解析测试或放宽JSON校验掩盖。

最终使用实际业务工具的原生函数调用，既不依赖模型在聊天文字中模拟工具协议，也不把不完整参数猜测为可执行操作。函数分片按 index 组装，名称、参数仍需本地校验。

## 最终方案：同一组任务连续跑两轮

| 场景 | 第一轮：状态 / 候选 | 第二轮：状态 / 候选 |
| --- | --- | --- |
| 八张卡讨论 | complete / 0 项 | complete / 0 项 |
| 追问按建议改 | ready / 2 项 | ready / 2 项 |
| 指定已有角色 | ready / 1 项 | ready / 1 项 |
| 新建地点 | ready / 1 项 | ready / 1 项 |
| 补现有章纲 | ready / 1 项 | ready / 1 项 |
| 正文润色 | ready / 1 项 | ready / 1 项 |
| 连续追问改稿 | ready / 1 项 | ready / 1 项 |
| 明确选方案 | ready / 2 项 | ready / 2 项 |

两轮共16/16通过，协议诊断与协议修复次数均为0。`complete` 表示纯讨论结束；`ready` 表示候选生成、等待作者确认。第二轮另断言了目标对象和字段：口吻任务仅 speechStyle，指定角色仅 identity/goals，正文仅当前章节 content，地点具有独立 summary/content，章纲对应当前章。每轮结束后核对数据库正文与原始输入完全一致。

第一轮35次模型调用：输入177459、输出12509 tokens；第二轮44次：输入228114、输出13613 tokens。含失败方案与单次排查探针，整个排查共127次调用，输入577507、输出41238 tokens。以上为接口 usage 数，不是扣费金额；未取得接口实付费用，不能据此声称实际花费多少。

## 自动回归与边界

新增测试覆盖：8项批量读取、坏DSML不回灌、空白修复、按端点启用JSON模式、原生函数参数分片/乱序、错误函数名拒绝、截断函数拒绝。整套282项测试通过。

这是小样本的工程回归，不保证所有真实任务永远成功，也不评价小说文笔质量。未模拟全部兼容网关、网络中断、超长上下文和服务商限流；这些情况仍需明确报错并保留已完成候选。实际工具参数校验失败可让模型根据错误修正，与协议解析错误区分。

接口依据：[DeepSeek Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[Chat Completions 的 tool_choice 与 thinking 限制](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON Output 的空白/替换行为](https://api-docs.deepseek.com/guides/json_mode/)。
